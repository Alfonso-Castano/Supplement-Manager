## Spacing Scale

Declared values follow the 4pt grid established in the existing design system:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon gaps, tight inline padding |
| sm | 8pt | Compact element spacing, badge padding |
| md | 16pt | Default HStack/VStack padding, form row spacing |
| lg | 24pt | Section padding, card internal padding |
| xl | 32pt | Layout gaps between major elements |
| 2xl | 40pt | Between major sections on preview screen |
| 3xl | 48pt | Bottom safe area clearance for CTA buttons |

Exceptions:
- Touch targets: minimum 44pt height on all tappable elements (HIG requirement)
- "Start Free Trial" CTA button: minimum 50pt height, full-width with 16pt horizontal margin
- Progress dot indicators: 8pt diameter, 6pt gap between dots

Source: `.claude/skills/stackwise-design/SKILL.md` (4pt grid canonical)

Accent (`.aquaPrimary` `#2A96A8`) reserved for:
1. "Start Free Trial" button fill (paywall placeholder CTA only)
2. "Next" / "Continue" navigation buttons in the onboarding coordinator
3. Active progress dot in step indicators (if implemented)

Accent is NOT used for: section headers, body text, decorative borders, card backgrounds, or any element not listed above.

Severity colors (`.criticalBG`/`.criticalFG`, `.advisoryBG`/`.advisoryFG`, `.positiveBG`/`.positiveFG`) appear on the preview screen summary card only — never used decoratively. They map directly to `AnalysisResults` data.

## Interaction Contracts

### Coordinator Navigation

| Transition | Mechanism | Notes |
|------------|-----------|-------|
| Step 1 → Step 2 | `NavigationStack` push | Back arrow active; user can revise health profile |
| Step 2 → Step 3 | `NavigationStack` push | Back arrow active; user can revise stack |
| Step 3 → Step 4 | `NavigationStack` push | Back arrow active; user can revise schedule inputs |
| Step 4 → Paywall | Replace / full-screen cover | One-way gate — no back navigation (D-02) |
| Paywall CTA tap | Dismiss coordinator | Sets `onboardingComplete = true`; ContentView renders TabView |

### Partial Resume (Crash Recovery)

Smart resume logic inferred from Core Data state (D-07). The coordinator evaluates on appear:

| Core Data State | Resume Point |
|-----------------|-------------|
| No `UserProfile` data (or empty age/weight) | Step 1 — health profile |
| `UserProfile` filled, zero `StackItem` records | Step 2 — stack entry |
| `StackItem` records exist, `wakeTime` is nil or default-untouched | Step 3 — schedule inputs |
| All data present, `onboardingComplete = false` | Step 4 — preview screen directly |

### Step 2 — Stack Entry Gate

- "Next" button disabled when `StackItem` count == 0
- Disabled state renders button at `.opacity(0.4)` with `.disabled(true)`
- Inline hint copy appears below the stack list when count == 0 (see Copywriting Contract)
- Button re-enables immediately when first item is added (reactive via `@Observable AnalysisStore`)

### Preview Screen — Summary Card

- Summary card renders two headline stats side-by-side using the declared Display type:
  - Interaction count pill: "N critical interactions found" (`.criticalFG` text if N > 0, `.textSecondary` if N == 0)
  - Schedule block count: "Your N-block schedule is ready" (`.sagePrimary` text)
- "See full analysis" is a `NavigationLink` push to existing `AnalysisView` — uses `.swHeadline` + `.aquaPrimary` tint
- Data sourced live from `AnalysisStore.results` and `ScheduleStore.result` — both must be invalidated before preview renders

### Paywall Placeholder — 4 Zones

Wireframe only. No visual polish. Structural zones for Phase 7 design handoff:

| Zone | Content |
|------|---------|
| Hero / value prop | Placeholder `Text` with zone label |
| Social proof | Placeholder `Text` with zone label |
| Pricing | Literal string: "14-day free trial, then $X/month" |
| CTA | "Start Free Trial" button (`.aquaPrimary` fill) + "Restore Purchases" plain text link |

CTA button writes `trialStartDate = Date()` to `UserProfile` (nil-guard enforces REQ-19), then sets `onboardingComplete = true` on both `UserProfile` and `AppState`.

## Transition Animations

Claude's discretion per CONTEXT.md:

- Coordinator step transitions: default `NavigationStack` push (slide from trailing edge) — no custom animation
- Preview → Paywall: `.fullScreenCover` presentation — bottom sheet rise, standard iOS modal
- Paywall CTA success: no custom animation — let TabView appear naturally via `onboardingComplete` state change
- Summary card on preview: `.animation(.easeIn(duration: 0.3), value: analysisResults)` on the stat numbers to handle late-loading data
