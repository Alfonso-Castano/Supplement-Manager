## Spacing Scale

All values in points (pt). Same multiples-of-4 principle as the web 8pt grid.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Inline gaps between badge elements, between dosage sub-label and item label |
| sm | 8pt | Spacing between items within a block row |
| md | 12pt | Vertical padding within item rows (sourced from existing ScheduleItemRow vertical padding pattern) |
| base | 16pt | Horizontal padding for block cards, section padding — matches `.padding(.horizontal, 16)` in OnboardingPreviewView |
| lg | 20pt | Internal card padding — vertical spacing within block cards (sourced from OnboardingPreviewView card internal padding) |
| xl | 24pt | Card internal padding top/bottom — matches `.padding(24)` in OnboardingPreviewView summary card |
| 2xl | 32pt | VStack section spacing — matches `VStack(spacing: 32)` in OnboardingPreviewView |
| 3xl | 48pt | Bottom scroll padding — matches `.padding(.bottom, 48)` in OnboardingPreviewView |

**Exceptions:**
- Notification permission screen CTA button: minimum height 50pt, matches `.frame(minHeight: 50)` from OnboardingPreviewView "See What You're Getting" button
- Touch targets for "Mark complete" toggle: minimum 44pt tall (iOS HIG minimum; the toggle row must have at least 44pt vertical tap area)
- safeAreaInset bottom padding on notification permission screen CTA: 16pt above and below the button container, matching OnboardingPreviewView's `.safeAreaInset(edge: .bottom)` pattern
- 12pt (md) — sourced from existing ScheduleItemRow vertical padding pattern; deviation from the 8/16 pair is intentional and traceable
- 20pt (lg) — sourced from OnboardingPreviewView card internal padding; deviation from the standard set is intentional and traceable

## Typography

All roles map directly to tokens in `DesignSystem.swift`. Use only these tokens — do not call `Font.system(size:weight:)` directly in Phase 6 views.

| Role | DesignSystem Token | Size | Weight | Usage in Phase 6 |
|------|-------------------|------|--------|-----------------|
| Screen title | `.swTitle1` | 28pt | semibold | Notification permission screen navigation title ("Never Miss a Dose") |
| Section header / block name | `.swHeadline` | 17pt | semibold | Block row header ("Morning", "Afternoon", "Evening") + time window |
| Body / item label | `.swBody` | 17pt | regular | Item label within block rows |
| Item sub-label | `.swCallout` | 16pt | regular | Dosage text beneath each item label |
| Value-frame supporting copy | `.swBody` | 17pt | regular | Notification permission screen benefit bullets and subtext |
| CTA button label | `.swHeadline` | 17pt | semibold | "Enable Reminders" button on permission screen |
| Mark complete label | `.swBody` | 17pt | regular | "Mark complete" label beside toggle |
| Completion summary | `.swFootnote` | 13pt | regular | Optional "2/3 blocks done today" summary line at top of Today tab |

**Weight rules:** Use `.semibold` for screen-level titles, block section headers, and CTA labels. Use `.regular` for all body copy, item labels, dosage text, and supporting copy. Never introduce a third weight in Phase 6 views.

**Line height note:** `swBody` line height is system-managed by SwiftUI. Do not apply an explicit `.lineSpacing()` modifier — the system default for SF Pro at 17pt is correct.

## Color

All tokens defined in `StackWise/DesignSystem.swift`. Use dot-syntax (`Color.aquaPrimary`, `.backgroundPage`, etc.) — do not hardcode hex values in Phase 6 views.

| Role | Token | Usage |
|------|-------|-------|
| Dominant surface (60%) | `.backgroundPage` | Notification permission screen background, Today tab scroll view background |
| Secondary surface (30%) | `.backgroundCard` | Block row cards in Today tab, summary card on notification permission screen |
| Accent primary (10%) | `.aquaPrimary` | CTA button tint (both screens), "Mark complete" toggle accent when active, tab bar tint (existing) |
| Accent secondary | `.sagePrimary` | Completed block state — block header foreground color when block is checked off |
| Text primary | `.textPrimary` | Item labels, block header text |
| Text secondary | `.textSecondary` | Dosage sub-labels, time window text in block header |
| Text tertiary | `.textTertiary` | Past-block dimmed text (applied via `.opacity(0.4)` on the entire block — see Interaction Design) |
| Border | `.borderDefault` | Block card border stroke (1pt), separator lines if used |
| Positive / completed | `.positiveFG` + `.positiveBG` | Completed state indicator on block row — "Completed" badge or checkmark icon on a checked-off block |
| Severity colors | `.criticalFG`, `.advisoryFG`, `.positiveFG` | NOT used in Phase 6 Today tab or permission screen — reserved for interaction badges only |

**Accent reserved for:**
- "Enable Reminders" button fill on notification permission screen
- "Mark complete" Toggle accent color (`.tint(.aquaPrimary)` on toggle)
- Tab bar item selected state (existing `.tint(.aquaPrimary)` on TabView — no change needed)
- NavigationLink text color on permission screen if any secondary link is needed

**Completed block color:** When a block is marked complete, the block header foreground switches to `.sagePrimary` and the "Completed" state indicator uses `.positiveFG` on `.positiveBG`. This mirrors the existing positive/synergy color use in ScheduleView badges.

**Past-block dimming:** Apply `.opacity(0.4)` to the entire past block container. Do not selectively dim individual elements — dim the VStack/card holding the entire block row at once. Exception: past blocks that are already checked off render at full opacity using the completed-state styling (D-19).

## Surface Specifications

### Surface 1: Notification Permission Screen (`NotificationPermissionView`)

**Pattern:** Full-screen gate — `if/else` branch in ContentView (not `.fullScreenCover`). Non-dismissible without tapping CTA. Matches the existing ContentView onboarding gate pattern.

**Layout:**

```
NavigationStack
  ScrollView (vertical)
    VStack(spacing: 32)
      [Icon / hero area]
        Image(systemName: "bell.badge.fill")
          .font(.system(size: 56))
          .foregroundStyle(.aquaPrimary)
      [Headline]
        Text("Never Miss a Dose")
          .font(.swTitle1)
          .foregroundStyle(.textPrimary)
          .multilineTextAlignment(.center)
      [Subtext]
        Text("Get a reminder at the right time for each block in your schedule.")
          .font(.swBody)
          .foregroundStyle(.textSecondary)
          .multilineTextAlignment(.center)
      [Benefit list — 3 bullets]
        VStack(alignment: .leading, spacing: 16)
          BenefitRow(icon: "clock.fill",  text: "Timed to your morning, afternoon, and evening blocks")
          BenefitRow(icon: "list.bullet", text: "Each reminder lists your specific supplements")
          BenefitRow(icon: "bell.slash",  text: "You control notifications any time in Settings")
  .padding(.horizontal, 16)
  .padding(.top, 24)
  .padding(.bottom, 48)
  .background(Color.backgroundPage.ignoresSafeArea())

safeAreaInset(edge: .bottom)
  Button("Enable Reminders") { ... }
    .buttonStyle(.borderedProminent)
    .tint(.aquaPrimary)
    .font(.swHeadline)
    .frame(maxWidth: .infinity)
    .frame(minHeight: 50)
    .padding(.horizontal, 16)
    .padding(.vertical, 16)
    .background(Color.backgroundPage)
```

**BenefitRow sub-component:**
```
HStack(spacing: 12)
  Image(systemName: icon)
    .foregroundStyle(.aquaPrimary)
    .frame(width: 24)
  Text(text)
    .font(.swBody)
    .foregroundStyle(.textPrimary)
```

**Navigation title:** None (no `.navigationTitle` — the headline Text replaces it for a cleaner full-screen feel). Set `.navigationBarHidden(true)` or omit NavigationStack if not needed for this gate view.

**Background:** `Color.backgroundPage.ignoresSafeArea()` — matches OnboardingPreviewView pattern.

### Surface 2: Today Tab (`TodayView`)

**Primary visual anchor:** The block card stack is the primary focal point. Block header names ("Morning", "Afternoon", "Evening") draw the eye first due to `.swHeadline` weight and full-card-width placement at the top of each card.

**Pattern:** NavigationStack + ScrollView containing VStack of block cards. Mirrors ScheduleView's block organization but with card-style containers instead of plain List sections, to support the per-block completed state and opacity dimming.

**Layout:**

```
NavigationStack
  ScrollView
    VStack(spacing: 16)
      [Optional completion summary — Claude's discretion: INCLUDE]
        HStack
          Text("N of 3 blocks done today")
            .font(.swFootnote)
            .foregroundStyle(.textSecondary)
        .padding(.horizontal, 16)
        .padding(.top, 8)

      [Block card × 3]
        BlockRow(block: "Morning",   items: schedule.morning,   ...)
        BlockRow(block: "Afternoon", items: schedule.afternoon, ...)
        BlockRow(block: "Evening",   items: schedule.evening,   ...)

    .padding(.top, 8)
    .padding(.bottom, 48)
  .navigationTitle("Today")
  .background(Color.backgroundPage.ignoresSafeArea())
```

**Completion summary:** INCLUDE. "N of 3 blocks done today" shows immediately below the navigation title. Updates reactively when check-off state changes. Text reads "0 of 3 blocks done today" / "1 of 3 blocks done today" / etc. When all blocks are done: "All done for today." in `.sagePrimary` foreground color.

**BlockRow sub-component layout:**

```
VStack(alignment: .leading, spacing: 0)
  // Block header
  HStack
    VStack(alignment: .leading, spacing: 2)
      Text(blockName)                          // "Morning"
        .font(.swHeadline)
        .foregroundStyle(isComplete ? .sagePrimary : .textPrimary)
      Text(timeWindowString)                   // "7:00 AM – 12:00 PM"
        .font(.swCallout)
        .foregroundStyle(.textSecondary)
    Spacer()
    if isComplete
      Label("Completed", systemImage: "checkmark.circle.fill")
        .font(.swFootnote)
        .foregroundStyle(.positiveFG)
        .padding(.horizontal, 8)
        .padding(.vertical, 4)
        .background(Color.positiveBG)
        .clipShape(Capsule())
  .padding(.horizontal, 20)
  .padding(.top, 20)
  .padding(.bottom, 12)

  Divider()
    .padding(.horizontal, 16)

  // Item list
  VStack(alignment: .leading, spacing: 8)
    ForEach(items) { item in
      HStack(spacing: 8)
        Circle()
          .fill(Color.aquaPrimary.opacity(0.25))
          .frame(width: 6, height: 6)
        Text(displayName(item.label))
          .font(.swBody)
          .foregroundStyle(.textPrimary)
        if !item.dosage.isEmpty
          Text(item.dosage)
            .font(.swCallout)
            .foregroundStyle(.textSecondary)
  .padding(.horizontal, 20)
  .padding(.vertical, 12)

  Divider()
    .padding(.horizontal, 16)

  // Mark complete row
  HStack
    Text("Mark complete")
      .font(.swBody)
      .foregroundStyle(isPast && !isComplete ? .textTertiary : .textPrimary)
    Spacer()
    Toggle("", isOn: $isBlockComplete)
      .labelsHidden()
      .tint(.aquaPrimary)
      .disabled(isPast && !isComplete)   // disabled if past and not yet checked off
  .padding(.horizontal, 20)
  .padding(.vertical, 16)

.background(Color.backgroundCard)
.clipShape(RoundedRectangle(cornerRadius: 12))
.padding(.horizontal, 16)
.opacity(isPast && !isComplete ? 0.4 : 1.0)   // dim entire card if past + uncompleted
```

**Empty state (no schedule items at all):**
```
ContentUnavailableView(
    "Nothing scheduled today",
    systemImage: "checkmark.circle",
    description: Text("Add items to your stack to generate a schedule.")
)
```
Matches the pattern used in ScheduleView for its empty state.

## Interaction Design

### Notification Permission Screen

| Interaction | Behavior |
|-------------|----------|
| Screen appears | Full-screen, non-dismissible. No swipe-to-dismiss. `if/else` branch in ContentView (not `.fullScreenCover`) so there is no dismiss gesture. |
| Tap "Enable Reminders" | 1. Fires `Task { try? await UNUserNotificationCenter.current().requestAuthorization(options: [.alert, .sound, .badge]) }` — 2. Sets `@AppStorage("notificationPermissionShown") = true` regardless of grant outcome — 3. ContentView branch switches to TabView |
| System permission dialog | Appears immediately after CTA tap, as a system modal overlaid on the permission screen |
| Permission denied | Screen exits normally; notifications are silently skipped by NotificationScheduler (D-11); no error state shown |
| Screen revisit | Never shown again — `@AppStorage("notificationPermissionShown")` flag prevents re-entry |

### Today Tab Block Rows

| Interaction | Behavior |
|-------------|----------|
| "Mark complete" toggle tap (current/future block) | Toggle animates to ON state with `.tint(.aquaPrimary)`. Writes `DailyCheckOff` record synchronously via Core Data upsert. Block header foreground switches to `.sagePrimary`. "Completed" badge appears with `.easeIn(duration: 0.3)` animation — matches the animation pattern in OnboardingPreviewView. |
| "Mark complete" toggle — past unchecked block | Toggle is `.disabled(true)`. Entire block card rendered at `.opacity(0.4)`. "Mark complete" label uses `.textTertiary` foreground. No tap response. |
| Past checked-off block | Toggle is `.disabled(true)` but block renders at full opacity with completed styling (sagePrimary header, positiveFG badge). Preserves user record. |
| Completion summary update | "N of 3 blocks done today" updates immediately when toggle fires — reactive via Core Data `@FetchRequest` observation. |
| Notification tap (from system) | App opens → `AppDelegate.userNotificationCenter(_:didReceive:)` fires → `appState.selectedTab = 1` → TabView switches to Today tab. No scroll-to-block behavior (D-20). |
| Notification arrives while app is foregrounded | System banner shown (`.banner + .sound + .badge`) per `willPresent` delegate method. No automatic tab switch. |
| Today tab appears with no items | `ContentUnavailableView` renders in place of block cards. |

### Tap Targets

| Element | Minimum tap area |
|---------|-----------------|
| "Enable Reminders" button | 50pt height, full screen width minus 32pt horizontal padding |
| Toggle row ("Mark complete") | 44pt height — achieved via `.padding(.vertical, 16)` on the HStack row (16+12+16 = 44pt with label height) |
| Block card — no tap target on card itself | Cards are not tappable containers; only the toggle row inside each card is interactive |

### Animation Contract

| State change | Animation |
|-------------|-----------|
| Toggle → completed | `.easeIn(duration: 0.3)` on block header foreground color and badge appearance — matches OnboardingPreviewView `.animation(.easeIn(duration: 0.3), value:)` pattern |
| Block opacity change | No animation — opacity is a static computed property based on time, not a user interaction |
| ContentView gate switch (permission screen → TabView) | Default SwiftUI `if/else` transition — no custom animation needed |
