## Tasks

### Task 1 — Wire `ScheduleStore.invalidate()` into `StackItemFactory`

**Files:**
- `StackWise/Features/Stack/AddItemView.swift` (EDIT)
- `StackWise/Features/Stack/StackItemFactory.swift` (no change — already accepts `onSaved`)

`AddItemView` currently calls:
```swift
StackItemFactory.create(formInput, in: context, onSaved: { analysisStore.invalidate() })
```

Change to:
```swift
StackItemFactory.create(formInput, in: context, onSaved: {
    analysisStore.invalidate()
    scheduleStore.invalidate()
})
```

Inject `@Environment(ScheduleStore.self) private var scheduleStore` into `AddItemView`.

**Verification:** Both stores invalidated on item save. No logic changes to `StackItemFactory`.

### Task 2 — Verify `ScheduledDose` Core Data writes

The `recompute()` method in `ScheduleStore` (written in Plan 04-02) must correctly:
1. Delete all existing `ScheduledDose` records associated with active items.
2. Create new `ScheduledDose` records with `timeBlock`, `suggestedTime`, `position`, and `stackItem` relationship set.
3. Call `context().save()` after writes (or use the existing `PersistenceController.shared.container.viewContext.save()`).

Verify by reading `ScheduleStore.recompute()` and confirming:
- Fetch request deletes all `ScheduledDose` via `NSBatchDeleteRequest` or explicit loop.
- New records are created with all 4 non-nil fields.
- `context().save()` is called and errors are handled (non-fatal: print to console).

If the writes are missing or incorrect (likely a stub gap from 04-02), fix them here.
